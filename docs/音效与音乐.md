# 果果答题 · 音效与背景音乐

> v1.0 · 2026-10-26 · 微信小游戏（`minigame/`）

## 0. 先回答「声音是不是也在项目里」

**是。** 小游戏的音频和图片、代码一样，都放在工程目录里一起打包上传：

```text
minigame/
  assets/audio/      ← 9 个 mp3，随代码包发布
    bgm-menu.mp3
    bgm-game.mp3
    bgm-result.mp3
    sfx-tap.mp3 / sfx-submit.mp3 / sfx-tick.mp3
    sfx-correct.mp3 / sfx-wrong.mp3 / sfx-coin.mp3
  js/audio.js        ← 播放器：解锁、切曲、音效池、开关、后台恢复
```

- 运行时用 `wx.createInnerAudioContext()` 播放，`src` 写**包内相对路径**（如 `assets/audio/bgm-menu.mp3`），不走网络、不用配域名白名单。
- 官方文档明确 `src` 可以填「代码包内文件路径」，并且两个平台都完整支持的格式是 **mp3 / aac / wav**（[音频播放文档](https://developers.weixin.qq.com/minigame/en/dev/tutorial/ability/audio.html)）。
- 所以 `.ogg` 全部转成了 mp3：iOS 微信对 ogg 支持不好，直接用 ogg 会出现「安卓有声、iPhone 没声」。
- 当前音频合计 **1.9MB**，小游戏主包上限 4MB，还有富余；以后再大就走分包或 CDN。

## 1. 最终选中的素材

### 背景音乐（3 首，循环播放）

| 用途 | 文件 | 原曲 | 时长 | BPM | 响度 | 听感 |
|---|---|---|---|---|---|---|
| 菜单 / 房间 / 榜单 / 我的 | `bgm-menu.mp3` | `ChillMenu_Loopable.ogg` | 63.5s | 68 | −15.5 LUFS | 温暖、松弛，适合等朋友 |
| 对局 | `bgm-game.mp3` | `TypeCastTheme_Loopable.ogg` | 59.0s | 114.8 | −14.3 LUFS | 明亮、有推进感，不抢答对音效 |
| 结算 | `bgm-result.mp3` | `VictoryLap_Loopable.ogg` | 42.4s | 68 | −14.9 LUFS | 庆祝、上扬，配领奖台 |

三首都用 `Loopable_ogg` 版本（原包另有一份 `Standalone_ogg`，是带前后奏的单曲版，不适合循环）。

### 音效（6 个）

| 事件 | 文件 | 来源 | 时长 | 处理 |
|---|---|---|---|---|
| 按钮点击 | `sfx-tap.mp3` | `button01a.mp3` | 0.17s | 裁掉头尾静音，末端淡出 |
| 点选项即提交 | `sfx-submit.mp3` | `blip01.mp3` | 0.40s | 裁头静音，末端淡出 |
| 倒计时每整秒 | `sfx-tick.mp3` | `blip01.mp3` | 0.11s | 取前 110ms，500Hz 高通，短促像「滴」 |
| 揭晓答对 | `sfx-correct.mp3` | `correct_answer1.mp3` | 0.98s | 裁掉尾部静音 |
| 揭晓答错 / 漏答 | `sfx-wrong.mp3` | `correct_answer1.mp3` | 1.05s | 降 4 个半音、压一点高频，同一动机的低音版 |
| 加分 / 进结算 | `sfx-coin.mp3` | `coin01.mp3` | 0.36s | 裁头尾 |

> 为什么答错是「答对降调」：同一段动机一高一低，听起来像一套音色，而不是东拼西凑。
> 素材里没有现成的 wrong 音，这比随便找个 buzz 更统一。

## 2. 为什么是这几首

从 `NotJamMusicPack_ogg` 的 20 首里，用 ffmpeg 量了时长、响度（EBU R128）、BPM、调性和频谱亮度，再按「果汁街机」的基调筛：

- **菜单**要松弛、耐听 → `ChillMenu`（68 BPM，中低亮度，循环 1 分钟不腻）。
- **对局**要有节奏但不能盖住音效 → `TypeCastTheme`（114.8 BPM，大调感，−14.3 LUFS，比 `DescendGameplay` 的 −9.5 LUFS 克制得多）。
- **结算**要喜庆 → `VictoryLap`。
- **排除**：`DescendGameplay`（太响、压音效）、`HaroldParanormalInstigatorTheme` / `KleptoLindaCaverns*`（恐怖 / 洞穴探索感）、`SeeingDouble` / `MeltdownTheme` / `SwitchWithMeTheme`（小调偏阴郁，和奶油水果调性冲突）。
- **备选**（想换风格时优先试）：`BreakbeatChips`（最街机，但只有 29s、亮度 3537Hz 容易抢音效）、`PitcherPerfectTheme`（143 BPM 更急）、`KleptoLindaTitles`。

> 说明：这是按客观指标 + 曲名 / 场景做的一轮筛选，**没有真正用耳朵试听**。上线前建议戴上耳机把三首各听一遍，尤其确认 `TypeCastTheme` 在 15 秒一题的节奏里不烦。

## 3. 什么时候响什么

| 时机 | 声音 | 代码位置 |
|---|---|---|
| 首页 / 创建 / 加入 / 房间 / 榜单 / 我的 / 规则 / 隐私 | `bgm-menu` 循环 | `app.go()` → `audio.setScene()` |
| 进入对局 | `bgm-game` 循环（160ms 淡出后切） | 同上 |
| 进入结算 | `bgm-result` 循环 + 一声 `sfx-coin` | `app.go()` |
| 任何按钮点击 | `sfx-tap` | `app.bindEvents()` 的 `onTouchEnd` |
| 点选项提交 | `sfx-submit`（不再叠 tap） | `app.answer()` 开头，点击即响，不等网络 |
| 开局 3-2-1 | 每整秒 `sfx-tick` | `app.tickSounds()`，按秒去重 |
| 抢答最后 3 秒 | 每整秒 `sfx-tick` | 同上 |
| 揭晓答对 | `sfx-correct`，若本题有加分再补一声 `sfx-coin`（延迟 260ms） | `app.revealSounds()` |
| 揭晓答错 / 没来得及答 | `sfx-wrong` | 同上 |

同一题重复下发（轮询）不会重复播报：`revealSounds()` 会比对上一帧的 `round.index` 和 `correctIndex`。

## 4. `js/audio.js` 接口

| 方法 | 作用 |
|---|---|
| `init()` | 读本地开关、设置静音策略；无音频能力时自动降级为空操作 |
| `unlock()` | 第一次触摸时解锁（iOS 自动播放限制），之后才会起 BGM |
| `setScene(name)` | 页面 → 曲目；同一首不重播，不同首淡出再切 |
| `suspend()` / `resume()` | 切后台 / 回前台（音频不会自动续播，必须手动 `play()`） |
| `play(name)` | 播一个音效，同名音效走 2 个实例的池子 |
| `setMusic(on)` / `setSfx(on)` | 开关并写入 `wx.setStorageSync('guoguo.audio.v1')` |
| `toggleMusic()` / `toggleSfx()` | 取反，返回新状态 |

对应 UI：**我的 → 背景音乐 / 音效**，右侧「开 / 关」胶囊，点一下即时生效并记住。

## 5. 音量与参数

| 参数 | 值 | 说明 |
|---|---|---|
| `BGM_VOLUME` | 0.32 | BGM 压到背景层，给音效让路 |
| `FADE_MS` | 160 | 切曲 / 淡入时长 |
| `POOL_SIZE` | 2 | 同一音效最多叠两层（安卓同时播放上限 10） |
| `sfx-tap` | 0.42 | 原始素材很响，压低 |
| `sfx-submit` | 0.50 | |
| `sfx-tick` | 1.00 | 素材本身很轻 |
| `sfx-correct` | 0.78 | |
| `sfx-wrong` | 0.62 | 答错不需要太刺耳 |
| `sfx-coin` | 0.90 | 素材偏轻 |

**手机静音**：默认 `obeyMuteSwitch = false`，手机静音时游戏仍有声（游戏内的开关才是最终控制）。
想尊重系统静音：把 `audio.js` 里 `ensureBgm()` / `contextFor()` 的 `obeyMuteSwitch = false` 删掉，或改成 `true`。

**和用户自己的音乐共存**：`init()` 里调了 `wx.setInnerAudioOption({ mixWithOther: false })`，进游戏会暂停用户在放的音乐（多数游戏的做法）。
想允许边听歌边玩，把它改成 `mixWithOther: true`；代价是两路声音会叠在一起。

## 6. 替换 / 新增

- **换曲**：同名覆盖文件即可，不用改代码。换完注意时长与首尾（用 `Loopable` 版本）。
- **加音效**：在 `SFX` 表里加一条 `{ src, volume }`，在需要的地方 `audio.play('新名字')`。
- **转码命令**（保持 96kbps / 44.1kHz 左右，体积可控）：

```bash
ffmpeg -y -i 原曲.ogg -c:a libmp3lame -b:a 96k -ar 44100 minigame/assets/audio/bgm-xxx.mp3
ffmpeg -y -i 音效.mp3 -af "atrim=start=0.015:duration=0.17,afade=t=out:st=0.13:d=0.04" \
  -ac 1 -c:a libmp3lame -q:a 5 minigame/assets/audio/sfx-xxx.mp3
```

- **体积**：音频超过 ~2.5MB 时，把 `assets/audio` 挪进分包（`game.json` 配 `subpackages`，进对局前 `wx.loadSubpackage`），或放 CDN 用 `wx.downloadFile` 缓存到本地。
- **循环接缝**：mp3 编码器有几十毫秒的延迟 / padding，循环点可能有极小的空隙。要求绝对无缝时只有两条路：换 ogg（安卓可以、iOS 不行），或用 `wx.createWebAudioContext()` + `decodeAudioData` 自己循环（代码量更大）。当前验收标准下接受这点空隙。

## 7. 授权（上线前必须确认）

- `NotJamMusicPack_ogg` 压缩包里**没有 LICENSE 文件**，无法从工程里证明授权范围。请回到下载页确认是否允许商用、是否要求署名。
- 四个 UI 音效（`button01a` / `correct_answer1` / `blip01` / `coin01`）看起来是 Kenney 一类免费音效包，但同样要以原始下载页的 License 为准（Kenney 通常是 CC0，无需署名）。
- 微信侧还要过「音频内容安全」，并在小游戏后台准备版权/授权说明。
- 建议在「我的 → 隐私与协议」或结算页脚加一行音乐署名（如果授权要求）。
